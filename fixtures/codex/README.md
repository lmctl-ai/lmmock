# Codex app-server fixtures

## Contract

One annotated `RPCHandler` program handles initialize/initialized, thread start,
strict resume, fork, turn start and interrupt. It enforces handshake and active
thread/turn ownership. Each cell supplies ordered notification data; malformed
usage and foreign terminal identifiers are emitted unchanged. Model selectors
and representative GPT/o-series families are data in the shared P0 manifest and
`wire.json`, generated by `tests/providers/codex/generate.py`.

The source contract is [Codex app-server](https://developers.openai.com/codex/app-server)
and lmctl's adapter at mono 8e334dda. Traffic is synthetic only. No vendor capture,
credentials, quota probe or model availability is implied. Auth/quota fixtures
are explicit app-server failures classified by the actual published lmctl client.
RPC route paths in the P0 manifest are logical method names, not HTTP routes.

## Real client boundary

Tests download npm lmctl 0.2.448 privately, then use its unmodified lmscript,
lm_agent/lm_batch_* bindings, Codex transport and failure classifier. The native
fake executable uses the existing generic RPC engine and contains no provider
policy, child provider or fallback. Every provider lookup is guarded to an owned
fake-bin. Its process PID is recorded and must be gone before fixture cleanup.
The test session marker is inside its temporary HOME, never the host's Codex home.

Tests assert real app-server argv/model fields, initialize ordering, thread
identity, dependent turns over one process, reply/error text, stdout/stderr/exit,
recorded session IDs (pre-turn RPC failures currently record null), one attempt per turn/start and 70 uncached +30 cached input,
12 output and4 reasoning tokens. P0 expectations reuse the shared validator and
checker. Process projections expose the real lm_classify_failure result; the
server never supplies an error_class to the test driver.

## Interrupt

A test-only observer watches delivery of the actual native turn/started record,
then signals after the client data callbacks and promise jobs. IPC carries SIGINT
to the published runner's own signal handler; native processes and bytes are unchanged.
The real adapter must send one matching turn/interrupt and receive the interrupted
terminal event. This works without a sleep, mock deadline or pacing rule. The
active cell waits for the protocol interrupt, not for a clock. Native stdout stays
protocol-only. Unit wire tests also exercise fork and interruption on every OS.

## Explicit limits

The strict controls deliberately remain runnable:

```
node tests/providers/codex/case.mjs --require-error-classes malformed-usage
node tests/providers/codex/case.mjs --require-error-classes wrong-turn-id
node tests/providers/codex/interrupt.mjs --require-finished-attempt
```

Published 0.2.448 accepts malformed usage as a successful turn while marking its
accounting counter_not_exposed/usage_unavailable. A foreign terminal followed by
EOF is a no-result error classified unknown. Thus specialized protocol/usage
error_class acceptance is **not qualified**. The regular controls require these
strict named assertions to expose the pinned client gaps; they never relabel them
as passing specialized-class coverage. Auth and quota classes do pass through the
real classifier.

On the observed Linux run, interrupt RPC/acknowledgement and process cleanup pass,
but cancellation can leave its attempt running with no ended_at/turn_outcome.
The strict finished-attempt control exposes this. Other platforms may finish it;
that legitimate stronger outcome is accepted without inferring universal settlement.
Fork is wire-qualified, not published-client-qualified: that adapter declares fork
manual and offers no public path to its unused fork helper. Native login/model
catalog, approvals and undocumented upstream variants remain separate coverage.

## Gates

The regular test.lms builds the native fake on all five platforms, executes P0
manifest cases with the privately downloaded client, runs the strict gap probes,
interrupt test and five compiled production-handler mutations. Removing the usage
event is also tested with an actual mutant executable against the published
client's accounting facts. Build failures, panics and stale anchors are not catches.
